# AETHER 1.0 — Capability Integration Matrix

**Created by Tabrej · License: Apache-2.0**

This matrix shows, for each of the thirteen capability programs (nine upstream-research +
the P10 deep-thinking, P11 full-stack, P12 project-intelligence and P13 business-logic
directives), exactly **which existing AETHER system each new capability integrates with**,
what it improves, and why a user should care. The invariant the program brief demands is preserved: **no competing
implementation of functionality that already works** — every new engine composes an
existing engine; none replace one.

## Cross-Program Integration Invariants

1. **Stable contracts.** Every program imports only from `src/core/programs/types.ts` and
   composes existing engines — no cross-program import cycles.
2. **No duplicate skill/workflow systems.** P01 discovers *into* the existing 540-skill
   catalog and *from* the existing 54 workflows; it adds a gate layer, not a second system.
3. **Failure is safe & honest.** A capability that needs a live backend (vision, browser,
   binary, network) reports `UNMEASURED_*` and a concrete `externalCommandToMeasure` — it
   never invents a result. This matches AETHER's `realBenchmarkEngine` discipline.
4. **Lifecycle-governed.** Each capability records `DISCOVER → … → REMOVE` state; only
   measured capabilities advance to `EXECUTE`/`MONITOR` (`registry.advanceLifecycle`).
