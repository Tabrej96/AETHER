Get started with AETHER

From clone to running all 21 capability engines in under 2 minutes. No build tools, no global installs, no mandatory API keys. AETHER's core runs entirely on zero runtime npm dependencies.

Node 18+ Zero runtime deps ~5 min full setup

Quick start — 60 seconds

1

Clone the repo

git clone https://github.com/Tabrej96/anythingwithaether.git && cd AETHER
2

Verify everything works (no npm install needed)

npx tsx bin/aether.ts validate

Expected: prints "OK" with the 711-component audit. ~5 seconds.

3

See it work

npx tsx bin/aether.ts programs

Runs all 21 capability engines. ~10 seconds. No API keys needed.

4

Install into your editor (optional)

./install.sh --all --target all-harnesses --write .
# or, on Windows / without bash:
npx tsx bin/aether.ts install --all --target all-harnesses --write .

Installation methods

Method A: From GitHub (development / first release)

git clone https://github.com/Tabrej96/anythingwithaether.git && cd AETHER
npx tsx bin/aether.ts programs

Method B: Published npm package

npm install aether-harness
npx aether programs

Method C: Unix one-liner

curl -fsSL https://raw.githubusercontent.com/Tabrej96/anythingwithaether/main/install.sh | bash -s -- --all

Method D: Selective domain pack

npx tsx bin/aether.ts install --target cursor --packs aws-cloud-vps,design-ui --mcp --write .

Configuration

AETHER has three configuration surfaces, all file-based and fully offline:

SurfaceFilePurpose
Provider credentials.envLive model endpoint for the GATE-01 end-to-end check
MCP permission policy.envLeast-privilege tool allow/deny for the MCP server
Harness install manifest.aether/manifest.jsonWhat install wrote, so uninstall removes exactly that

Optional: .env for live model

Copy the template and fill in the block you need:

cp .env.example .env

Then edit .env with your provider settings:

# Live model endpoint (optional — all engines run without it)
AETHER_LIVE_PROVIDER_URL="https://api.example.com/v1"
AETHER_LIVE_PROVIDER_KEY="your-key"
AETHER_LIVE_PROVIDER_MODEL="your-model-id"
AETHER_LIVE_PROVIDER_VENDOR="anthropic"  # or "openai-compatible"
AETHER_LIVE_PROVIDER_IN_USD_PER_M="0"
AETHER_LIVE_PROVIDER_OUT_USD_PER_M="0"

# MCP permission policy (optional, least-privilege)
AETHER_MCP_PERMISSION_POLICY='{"deniedTools":[],"requireApprovalFor":[],"approvedTools":[]}'
Never commit a real API key. .env is gitignored. .env.example is committed with placeholder values only.

Your first project

Let's walk through a real workflow: building a product strategy using AETHER's P12 Project Intelligence engine.

Step 1: Run the classifier

npx tsx bin/aether.ts strategy "Build a dental clinic booking platform"

Output: multi-label classification (e.g. BOOKING primary, SAAS secondary) + effort policy + PROJECT_STRATEGY.md.

Step 2: Run the business-logic planner

npx tsx bin/aether.ts business "Build a multi-tenant SaaS billing platform with checkout and subscriptions"

Output: domain model, lifecycle state machines, edge-case catalog, possibility engine, and metric discipline audit.

Step 3: Run the quality panel

npx tsx bin/aether.ts panel "Build a multi-tenant SaaS billing platform"

Output: nine-reviewer verdict (business analyst, domain specialist, financial-logic, security, QA, etc.) with evidence-gated findings.

Step 4: Run the evolution suite

npx tsx bin/aether.ts evolve

Output: regression suite run + measured promote/hold/reject demonstration. Mean score and no-op handling verified.

Troubleshooting

Every AETHER failure state is designed, labeled, and reported. The system never fails silently. See docs/TROUBLESHOOTING.md for the full table.

Common issues

SymptomCauseFix
npm install fails on peer-dep conflict First install needs the legacy flag npm install --legacy-peer-deps (one-time)
install.sh syntax errors On Windows without bash/WSL Use npx tsx bin/aether.ts install ... instead
UNAVAILABLE_NO_CREDENTIALS .env missing or incomplete Copy .env.example and fill in your keys. Expected on a clean clone.
Harness says UNAVAILABLE Needs a host daemon (OpenHands, Browser Use, Skyvern) Run the listed external command, then re-run the benchmark
Task stays QUEUED after a crash Expected — PersistentTaskQueue.recover() demotes in-flight tasks on restart Re-run and they drain automatically
MCP tool returns BLOCKED_BY_SECURITY_GATE A built-in gate denied the call Review the result payload for the reason. This is the safe path.

Health check

Both commands are deterministic and offline:

npx tsx bin/aether.ts programs    # registry + provenance audit -> "OK"
npx tsx bin/aether.ts validate    # all 711 components validated

If either exits non-zero, the failure message names the exact component or gate.
