The nine programs

Each program followed the same 12-step process: clone the upstream repo → verify ownership & license → inspect the architecture → extract the strongest idea → re-implement it as a native, tested AETHER engine → benchmark it. Full research notes live in docs/AETHER_NINE_PROGRAM_RESEARCH.md.

Every engine here is original Apache-2.0 code. The projects below are credited as inspiration sources only — no AGPL/GPL code is linked into AETHER's core. See benchmarks for the measured numbers and compare for the side-by-side builds.

P01 — Development Intelligence

Inspiration: affaan-m/ECC (MIT) · obra/superpowers (MIT)

Turns ECC's skill/trigger catalog and Superpowers' brainstorm→plan→TDD discipline into one composed, gate-enforced pipeline: deterministic skill discovery, a research-first gate, a Red-Green-Refactor state machine, a debugging hypothesis ledger, and instinct extraction into the memory promotion gate. It does not create a second skill system — it ranks and gates the existing 540.

Measured: happy path discovers 3 ranked skills and clears every gate; a research-missing task is blocked with 2 explicit reasons.

npx tsx bin/aether.ts programs → P01 · skills-discovered-in-happy-path = 3

P02 — Reverse Intelligence

Inspiration: morluto/rea (MIT)

An isolated, permission-controlled reverse-engineering subsystem: application architecture extraction, dependency discovery, structure reconstruction, and automated reporting — gated by a hard assertAuthorization() pre-condition. It only operates on software the user owns or is authorized to investigate (OWNED, AUTHORIZED_LICENSE, CTF_TARGET, or DEFENSIVE_SECURITY, with recorded evidence). Binary / network / UI-behavior slots are declared UNMEASURED rather than fabricated.

Measured: unauthorized targets throw before any data is read; a 4-module synthetic service reconstructs to 4 layers and 2 external dependencies.

P03 — Autonomous Execution

Inspiration: All-Hands-AI/OpenHands (MIT) · FoundationAgents/OpenManus (MIT)

Architecture comparison, not runtime duplication: OpenHands' event-stream resumption + OpenManus' plan-and-act loop become a step-level resumable executor. A goal becomes a dependency-ordered plan; every step has a deterministic verify predicate; a crash checkpoint records completed steps + state; resume replays only the failed steps; dependents of a failed step are skipped, not run against stale state.

Measured: run 1 completes 2/4 and checkpoints; resume from that checkpoint completes 4/4 and self-verifies. Exactly the 2 remaining steps finished after resume.

P04 — Multi-Agent Orchestration

Inspiration: microsoft/autogen (archived — successor: Microsoft Agent Framework)

AutoGen is used strictly as an architectural reference (event bus, group chat, agent teams) — no AutoGen dependency, no Agent Framework dependency. The AETHER-native orchestrator: append-only event log, task-dependency-graph parallel waves, retry-once-then-fail-fast, group-conversation turns between waves, and deterministic termination when a capability is missing (no unbounded re-scheduling).

Measured: 3-task DAG executes in 2 parallel waves with 1 deterministic retry and 1 group-conversation turn; a missing-capability task fails fast with named evidence.

P05 — Browser Intelligence

Inspiration: browser-use/browser-use (MIT) · vercel-labs/agent-browser (Apache-2.0)

One unified Browser Engine with ranked interaction strategies: deterministic DOM/ARIA locators and compact [ref] accessibility snapshots first; form-fill and screenshot verification second; vision coordinates only as an escalation (reported UNMEASURED without a live backend — never a fabricated hit). Live execution is delegated to the P07 provider abstraction.

Measured: a 5-node form snapshot costs 15 tokens vs ~190 raw-DOM tokens — 92% saved; labeled inputs resolve at ≥0.9 confidence; unresolvable queries return null + escalation.

P06 — Visual Computer Intelligence

Inspiration: Skyvern-AI/skyvern (AGPL-3.0, out-of-process) · microsoft/OmniParser (CC-BY-4.0)

The perception → reasoning → action → verification loop: detected elements with normalized bboxes, deterministic grounding (role × confidence × label), click/coordinate actions, and a verification step that only counts when the observed post-action state matches the expectation. Below the confidence floor the loop aborts and asks for a real vision backend — it does not guess pixels. Skyvern is studied out-of-process only (AGPL); OmniParser's grounding concept is reimplemented clean-room.

Measured: verified goal reached in 1 step; ungrounded intent aborts in 1 step with an UNMEASURED note.

P07 — Browser Runtime

Inspiration: lightpanda-io/browser (AGPL-3.0-only) · microsoft/playwright (Apache-2.0)

A provider abstraction that selects a browser backend per task: Playwright's full cross-browser capability surface, Lightpanda's resource-efficient CDP subset, or bare headless Chromium. A provider is compatible only when it genuinely covers every required capability; gaps are returned with verificationRequired: true. Compatibility is verified per task, not assumed — Lightpanda is not treated as a drop-in Chromium.

Measured: 4 task profiles verified — 3 fully-compatible picks; the WebGL-capture profile is correctly flagged unverified.

P08 — Workspace & Knowledge Ecosystem

Inspiration: HeyPuter/puter (AGPL-3.0-only, out-of-process) · obsidianmd/obsidian-releases (public registry)

Per the program brief: Obsidian Releases contains no proprietary app source — it is the public plugin/theme registry, which is exactly what this program studies. A Markdown vault becomes a knowledge graph (wiki-links + tag clusters, degree, orphans); workspace planning places notes into project folders; plugin discovery audits every candidate's permissions and SPDX license before it may register.

Measured: 4-note vault → 4 deduplicated edges, orphan detected; 4 files planned into 3 folders; 1 plugin discovered with 1 audited permission.

P09 — Creative & Visual Intelligence

Inspiration: Comfy-Org/ComfyUI (GPL-3.0, out-of-process) · mrdoob/three.js (MIT)

Modular generation backend + separate 3D frontend, as the brief requires. The ComfyUI node-graph concept becomes a clean-room, backend-agnostic topological scheduler (cycle-safe, unknown backends resolve to null rather than a guess); Three.js' scene graph becomes an in-process model with deterministic render order and a draw-call estimate. ComfyUI itself plugs in as an out-of-process backend only — GPL code is never linked into the Apache-2.0 core.

Measured: 4-node generation graph → 4 topological layers; cyclic graph throws; 3-object scene → render order [root, m1, l1], 2 draw calls.

The integration contract

Every capability is registered with full provenance and a controlled lifecycle:

DISCOVER → INSTALL → VALIDATE → REGISTER → EXECUTE → MONITOR → UPDATE → REMOVE

Files: src/core/programs/types.ts (contracts) · src/core/programs/registry.ts (lifecycle manager) · docs/AETHER_INTEGRATION_REGISTRY.md (machine-generated registry).
